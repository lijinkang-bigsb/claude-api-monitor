# Claude Code API 状态小监视器

## 行为边界

- 把本机正式安装目录视为 `E:\Tools\claude-api-monitor`；仅当该目录不存在时，要求用户提供安装目录。
- 导入本 Skill 本身不会启动程序、不会修改 DSH 的 API 设置，也不会让 DSH 的请求自动经过监视器。
- 只在用户明确提出“启动监视器”“看监视器”“停止监视器”“隐藏 DSH 请求”或排查对应故障时操作。
- 不读取、展示、写入或要求用户发送 API Key、`ANTHROPIC_AUTH_TOKEN`、提示词或回复正文。
- 不直接编辑 `C:\Users\LJK\.claude\settings.json`、`config.json` 或 DSH 的 API 配置；这些文件由 CCswitch、用户或监视器自身负责。

## 启动与关闭

1. 建议用户在 VS Code 中按 `Ctrl+Shift+B` 启动“API 监视器”任务。它会在底部终端常驻，并将 Claude Code 临时接到 `127.0.0.1:3456`。
2. 不要在已经运行时重复启动第二个实例。若用户不确定，先让其查看 VS Code 底部是否已有“API 监视器”终端。
3. 关闭时，让用户在**监视器终端**按 `Ctrl+C`。不要建议使用终端垃圾桶或强制结束进程；正常关闭会把 Claude Code 恢复为直连上游 API。
4. 监视器启动后，DSH 仍使用它自己在 DSH 界面中填写的 API。只有 DSH 的 API 基址被人为设为 `http://127.0.0.1:3456` 时，DSH 请求才会经过监视器。

## 查看与切换显示

让用户点击监视器终端后直接按键，不需要按 Enter：

- `M`：暂停或恢复所有状态行的显示；请求仍会正常转发。
- `D`：隐藏或显示 DSH 请求；只影响终端显示，不改变 DSH 网络、模型、密钥或缓存。
- `Ctrl+C`：停止监视器并恢复 Claude Code 直连。

状态行的格式为“客户端 | 模型 | HTTP 状态码 | 耗时 | token”。监视器不记录请求正文或密钥。

## 排查

- `200`：请求成功。
- `401` / `403`：认证或账户权限问题，应检查当前服务商的密钥与权限。
- `429`：服务商限流或额度不足。
- `500`：上游服务内部错误。
- `502` 且提示“本地监视器无法连接上游 API”：监视器正在运行，但当前真实上游地址不可用；检查 CCswitch 当前选择、上游服务与网络。
- `Connection refused` 或无法连接 `127.0.0.1:3456`：Claude Code 仍指向本地端口，但监视器已经不在运行。先重新按 `Ctrl+Shift+B` 启动；若仍失败，退出并重开 VS Code，让恢复保护或 CCswitch 重新写入真实上游地址。

不要把 502 误判成 DSH 故障；先确认问题请求的客户端列是 `Claude` 还是 `DSH`。
